> 依据文档：
> - `技术选型.md`（技术方案 v2，§7 已细化为文件级目录树）—— 以下简称「**选型**」

## 一、拆分原则与范围

1. **严格文档对应**：每个任务都绑定 `选型` 或 `约束` 的某一节/某一条，确保不漏需求点、不凭空加项。
2. **颗粒度可执行**：任务细化到「一个文件 / 一个组件 / 一个接口 / 一张表 / 一个配置」级别，可直接派工与验收；文件级落点直接引用 `选型 §7` 目录树。
3. **依赖显式标注**：每条任务标注 `依赖（前置）`、`并行组`、`验收要点`；并行任务之间无强依赖，可同时开工。
4. **里程碑映射**：整体对齐 `选型 §10` 的 M1–M4，便于分阶段验证。
5. **待确认项（Gate）**：`选型 §11` 的「鉴权」「实时性」两条尚未定案，作为阻塞 Gate 标注，不阻塞其余任务但影响部分任务形态。
