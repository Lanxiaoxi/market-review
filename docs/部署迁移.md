# 部署迁移指南（本地 → 服务器）

> 适用场景：把本机的 `market-review` 项目 + 已有数据库迁移到 VPS 上运行。
> 后端端口固定为 **8668**（内部服务，由 Caddy 反代；前端静态文件由 Caddy 托管，同域无 CORS）。

## 一、服务器上需要的东西

| 项 | 说明 |
|---|---|
| 代码 | `git clone git@github.com:Lanxiaoxi/market-review.git`（或 `git pull`） |
| Python | 3.11+（后端） |
| [uv](https://docs.astral.sh/uv/) | 依赖管理（systemd unit 依赖它，`uv sync` + `uv run`） |
| Node.js | 18+（仅当在服务器上构建前端；也可直接上传本地 `web/dist`） |
| Caddy | 反向代理（或改用 Nginx，需自行配 `/api` 转发） |

## 二、必须手动上传的非 git 文件

`.gitignore` 里排除、`git pull` 不会带过去的文件：

| 文件 | 说明 |
|---|---|
| `api/.env` | **必须**。含 `TUSHARE_TOKEN` / `THS_API_KEY` / `APP_ENV`；不传则实时数据源全部失效（中债收益率无需 key） |
| `api/data/app.db` | 数据库本体（约 150MB，含全部 L2 历史数据） |
| `api/data/app.db-wal` / `app.db-shm` | **WAL 伴生文件，不能漏**——最新写入都在 WAL 里 |

**WAL 处理（二选一）**：
- 推荐：本地先停 API（`systemctl stop market-api` 或 Ctrl+C）→ 停进程时 SQLite 自动把 WAL 合并进 `app.db` → 确认 `app.db-wal` 为 0 字节 → **只传 `app.db`**
- 或：`app.db` + `app.db-wal` + `app.db-shm` 三个一起传（复制时本地 API 不要运行）

前端：服务器构建（`cd web && npm install && npm run build`）或直接把本地 `web/dist/` 传过去。

## 三、部署步骤

```bash
# 1. 拉代码（放到 /var/www/market-review）
cd /var/www
git clone git@github.com:Lanxiaoxi/market-review.git
cd market-review

# 2. 上传 .env 与数据库
#   scp api/.env → api/.env
#   scp api/data/app.db → api/data/app.db（含 WAL 则一并传）

# 3. 安装后端依赖
curl -LsSf https://astral.sh/uv/install.sh | sh
cd api && uv sync

# 4. 前端（二选一）
cd ../web && npm install && npm run build
#   或直接把本地 web/dist 传到 web/dist

# 5. 注册 systemd 服务（后端 8668）
sudo cp deploy/market-api.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now market-api

# 6. Caddy 反代（改 deploy/Caddyfile 里的域名）
sudo cp deploy/Caddyfile /etc/caddy/Caddyfile
sudo caddy reload
```

## 四、验证

```bash
curl 127.0.0.1:8668/api/health      # → {"status":"ok"}
curl 127.0.0.1:8668/api/overview    # → 10 个指数等完整数据
curl https://你的域名/              # → 前端首页
```

## 五、注意事项（踩坑清单）

1. **数据库目录权限**：systemd unit 用 `User=www-data`，`api/data/` 及 `app.db` 必须 www-data 可读写：
   ```bash
   sudo chown -R www-data:www-data /var/www/market-review/api/data
   ```
   否则 SQLite WAL 写不进去，服务启动即失败。
2. **`api/data` 目录必须存在**：代码启动时会自动创建，但父目录路径要对。
3. **不要设 `BACKFILL_ON_STARTUP_DAYS=250`**：数据库已完整，`fetch_log` 会跳过已拉取日期，但没必要触发一次全量扫描。保持 `0`（默认）。
4. **写入接口鉴权（可选）**：如担心公网写接口被滥用，在 `api/.env` 里加 `API_TOKEN=xxx`，写操作需携带 `X-API-Token` 头。
5. **不用 Caddy 的话**：若直接暴露 8668 或改用 Nginx，需在后端配置 `CORS_ORIGINS`（逗号分隔白名单）解决跨域。

## 六、迁移后的运维

- **每日 15:35（Asia/Shanghai）自动固化**：服务器常驻后，收盘快照、分时、国债收益率、期货主力连续每天自动积累，不再依赖本机在线。
- 手动触发回填：`curl -X POST "http://127.0.0.1:8668/api/history/backfill?days=250"`（带 API Token 时加 `-H "X-API-Token: xxx"`）。
- 备份：`deploy/backup.sh` 可参考；数据库只需备份 `api/data/app.db`（停服后拷贝）。

## 七、端口约定

| 服务 | 端口 |
|---|---|
| FastAPI（内部，仅本机回环） | **8668** |
| Caddy（对外 80/443） | 80/443 |
| Vite dev（仅本地开发） | 5173（代理 `/api` → 8668） |
