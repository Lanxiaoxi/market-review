## L2 行情持久层（后端数据存储策略）
- 任务来源：用户 @scene#15"日常开发"，要求设计数据存储策略，用本地库替代大量数据源 API 请求，且每天新数据要能获取、不重复拉
- 核心原则：**按数据可变性分层而非按 TTL 分层**。以 trade_date 为主维度，已定格数据永久存储零回源，盘中数据才走内存短 TTL
- 三层读取路径：L1 内存 TTL → L2 SQLite（按 trade_date 命中）→ L3 数据源 API
- 新增 10 张表（api/app/models/market_data.py）：trade_calendar / stock_daily / market_daily_agg（预聚合，查询 O(1)）/ index_daily / sector_daily / futures_daily / intraday_bar / stock_name / fetch_log（去重闸门）/ series_cache
- 明细 + 聚合双写：stock_daily 存原始行可回溯重算，market_daily_agg 存预聚合避免每次扫 60×5400 行
- 去重靠 fetch_log(domain, ref_key) 唯一，回填前查差集、落库后登记
- provider 新增 5 个回填专用域（stock_daily_raw / index_range / sector_range / stock_names / calendar）；**THS 快照接口只能取当日，历史区间只有 Tushare 能补**
- 回填编排（api/app/services/backfill.py）：区间优先（指数/板块/期货），日级兜底（个股日线，Tushare daily 单次即全市场某天）
- 触发：15:35 定时任务（回填近 5 日 + 快照）/ POST /api/history/backfill?days=N / BACKFILL_ON_STARTUP_DAYS 启动自动
- 关键实现细节：回填后必须 clear_all() 清内存缓存，否则请求仍拿回填前旧数据
- 收益：limit-counts 冷启动 120 次 → 0；overview 76 → 0~3；sectors 35 → 0；watchlist N → 0；进程重启 0
- 测试 51 passed。核心保障是 tests/test_l2_read.py：把各模块 fetch_domain 换成抛错探针，接口仍 200 即证明零回源
- 顺手修的既有 bug：① db.py 迁移在表未注册时 ALTER TABLE 崩溃（加 _table_exists 守卫 + db.py 集中注册所有模型）② ths_provider.py 用了 datetime 却没导入 ③ 测试间数据串味（conftest 改 autouse 清库 + 清内存缓存）
- 抽了 api/app/services/buckets.py 统一分档逻辑（原 tushare/ths 各实现一份，语义相同）
- 已知限制：历史板块领涨股为 `—`（需 sector_member 表才能本地算）；daily_snapshot 仍是 JSON blob
